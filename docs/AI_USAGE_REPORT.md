# AI Usage Report

**AI tool used:** Claude Sonnet

## What I asked AI to do
1. Produce a phased architecture and implementation plan for a student ticketing platform (roles, data model, API, SLA logic, folder structure) before writing any code.
2. Generate complete backend and frontend code, phase by phase, waiting for me to run and report results/errors before moving to the next phase.
3. Debug real errors I hit while running the code (a nested Git repository, a missing database name in the MongoDB connection string, PowerShell-specific command differences) and produce corrected, complete files.
4. Generate this set of documentation files from the actual decisions and results discussed during development.

## Prompt that was most useful
The initial instruction to plan first, then build in small, testable phases, and to never claim something works without my confirmation. This kept each phase verifiable and made debugging tractable under a tight deadline.

## Code generated by AI
All backend (Express routes/controllers/services/models/middleware) and all frontend (React components, pages, services, contexts) code in this repository was AI-generated, phase by phase, based on my confirmed requirements at each step.

## Code I modified
No manual code edits beyond what the AI provided were reported back during this project; all code was copied in as given and tested as-is at each phase.

## AI output that was incorrect

### Issue 1: MongoDB database name omitted
**AI output:** the example `MONGODB_URI` did not make the database name obvious enough, and my initial Atlas connection string had no explicit database name before the query string.
**How identified:** after passing all authentication tests, I could not find an `educare` database or `users` collection in Atlas's Browse Collections view.
**Fix:** added the explicit database name (`/educare`) to the connection string, restarted the server (which then logged `database: educare`), and re-ran the seed script.

### Issue 2: Nested Git repository
**AI output/situation:** a `.git` folder existed inside `server/`, separate from the repository root, which made `git add .` fail with `'server/' does not have a commit checked out`.
**How identified:** `git status` at the repo root returned that error instead of listing individual files.
**Fix:** confirmed the inner repository had no commits, deleted `server/.git`, and moved `.gitignore` to the repository root (it had initially been created inside `server/`, which would not have protected `client/`'s `node_modules` and `.env` once the frontend was added).

## How I validated AI-generated code
Every phase was manually tested before moving to the next:
- **Auth (Chunk B):** 12 Postman tests covering registration, forced-STUDENT role, duplicate email, validation errors, login, wrong credentials, protected routes, invalid/expired tokens, and role authorization. All passed.
- **Tickets/workflow/SLA (Chunk C):** 26 Postman tests covering creation, duplicate protection, ownership (404 for other students), status transitions, claiming, resolving, closing, reopening, reassignment, priority/SLA recalculation, and filtering. All passed.
- **Comments/activity (Chunk D):** 21 Postman tests covering validation, visibility rules (internal notes hidden from students), authorization, the closed-ticket restriction, and the automatic WAITING_FOR_STUDENT → IN_PROGRESS transition on student reply. All passed.
- **Frontend (Chunks E–F):** manual browser testing of login/register validation, session persistence on refresh, role-based redirects, dashboards, ticket creation, and responsive layout at mobile width.
